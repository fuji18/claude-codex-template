# モード C(縮退)— チケット 1 件を単独で完走する

Claude の枠が尽きている期間の手順です。**あなたが計画から実装・コミットまでを 1 人で担当します。**

縮退モードは行き止まりではなく**キュー**です。あなたはブランチにコミットを積むだけで、PR は作りません。Claude の枠が回復したら、通常フローの検収を経て PR に合流します。

> **この手順が特別な理由**: モード A・B の委託は `delegate-codex.sh` を経由し、そこで機械的な入口検査が掛かります。**モード C はその経路を通らない唯一の経路**です。同じ検査をあなた自身が実行する必要があります。飛ばさないでください。

---

## 0. 入口検査(必ず最初に、この順で)

5 つすべてを通してから作業を始めます。**1 つでも通らなければ作業を始めずに人間へ報告して停止してください。**

### 検査1: 自分がモード C で動いているか

```bash
cat .harness/mode 2>/dev/null || echo "(未設定)"
```

`degraded` **以外**(未設定を含む)なら、この手順を続けないでください。モード A・B は司令塔がいる前提の運用で、**コミットが禁止されています**。人間に「`.harness/mode` を `degraded` にするか、通常の委託経路(`delegate-codex.sh`)を使うか」を確認して停止します。

### 検査2: 保護ブランチにいないか

```bash
git branch --show-current
cat .claude/branch-policy.json
```

現在のブランチが `protectedBranches` に載っている場合、**自分で作業ブランチを切ってください**。モード C では司令塔がいないため、切らないと `.husky/` の git hook がコミットを弾いて詰みます。

```bash
git switch -c feature/[作業名]
```

接頭辞は `allowedPrefixes` に従います。

### 検査3: git hook が有効か

```bash
git config --get core.hooksPath
```

`.husky/` が存在するのに、この値が**空** または**実在しないディレクトリ**を指している場合は、作業を始めずに人間へ報告して停止してください。husky が丸ごと無効 = 保護ブランチへのコミットを止めるベンダー非依存の層が存在しない状態です。sandbox はネットワーク無効なので、あなた自身では復旧できません(`npm ci` が必要)。

> 値を `.husky` と決め打ちで比較しないでください。**husky v9 が設定するのは `.husky/_` です。**

> **この値を自分で書き換えないでください。** 検査は「有効かどうかを確認する」ためのもので、
> 通らなければ人間に報告して停止します(復旧には `npm ci` が必要で、sandbox からはできません)。

### 検査4: 依存がインストール済みか

`AGENTS.md` の機械可読マーカーからプローブコマンドを取り出して、1 回実行します。

```bash
sed -n 's/^[[:space:]]*<!--[[:space:]]*verify-probe:[[:space:]]*\(.*[^[:space:]]\)[[:space:]]*-->[[:space:]]*$/\1/p' AGENTS.md | head -1
```

出力されたコマンドを実行し、**失敗したら停止して人間へ報告してください**。ネットワーク無効の sandbox では依存を自分で入れられないため、この状態で進めても何も完遂できません。

### 検査5: `.git` に書き込めるか(コミットの成立条件)

```bash
touch .git/.probe 2>/dev/null && rm -f .git/.probe && echo GIT_WRITABLE || echo GIT_READONLY
```

**`GIT_READONLY` なら作業を始めないでください。** sandbox の既定では `.git` が読み取り専用で、この状態では **`git add` すら失敗します**(実機で確認済み)。モード C はあなたがコミットを積むことで成立するので、ここが通らないと何もできません。

次を人間に伝えて停止してください。

> `.git` に書けないためコミットできません。次のコマンドで起動し直してください:
>
> ```bash
> codex --sandbox workspace-write -c 'sandbox_workspace_write.writable_roots=[".git"]'
> ```

> **この許可はモード C の起動時にだけ渡します。** `.codex/config.toml` には書きません。モード A・B(`delegate-codex.sh` 経由)はコミット禁止の運用で、そこでは `.git` が書けないこと自体が防衛線になっているためです。

### 検査の結果を報告する

5 つ通ったら、1 行で報告してから次に進みます。

```
入口検査 OK: mode=degraded / branch=feature/xxx / hooksPath=.husky/_ / probe=pass / git=writable
```

## 1. 作業単位を決める

**`gh` は使えません**(sandbox はネットワーク無効)。Issue の本文を自分で取得することはできないので、**要求は人間がプロンプトで渡します**。

- 要求が渡されていなければ、**推測で始めずに人間に聞いてください**
- 既存の作業を再開する場合は、未完了の `tasklist.md` を探します

```bash
ls -1d .steering/*/ | tail -5
```

未完了(`- [ ]` が残っている)ステアリングがあれば、新規に作らず**その続きから再開します**。

---

## 2. 計画を書く(steering 3 点)

```bash
date +%Y%m%d
```

`.steering/[YYYYMMDD]-[短い名前]/` を作り、3 ファイルを置きます。

| ファイル          | 内容                                                            |
| ----------------- | --------------------------------------------------------------- |
| `requirements.md` | 人間から渡された要求・スコープ・受け入れ条件                    |
| `design.md`       | 実装方針。**冒頭に `<!-- status: ready -->` を書く**            |
| `tasklist.md`     | `- [ ]` のチェックリスト。**1 タスク = 1 コミットの粒度**にする |

> **モード C では設計もあなたが書きます。これは例外運用です。** 通常「設計判断は移管しない」のが原則で、モード C はそれを**延期しているだけ**です。あなたが書いた `design.md` は、Claude 復帰時に**それ自体がレビュー対象**になります。

---

## 3. 実装ループ(1 タスクずつ)

`tasklist.md` の項目を**上から 1 つずつ**片付けます。1 タスクごとに次の 5 手順を回してください。

1. **実装する**
2. **変更したファイルだけに** lint / フォーマットを掛ける
3. 型チェックと関連テストを通す
4. `tasklist.md` を `- [x]` に更新する
5. コミットする

> **`npm run format`(全体フォーマット)を回さないでください。** 人間や司令塔が並行して `docs/` を書いている可能性があり、その編集を書き潰します。範囲を絞るのは行儀ではなく競合回避です。

> **`tasklist.md` の逐次更新と、コミット前の品質チェックは行儀ではなく要件です。** あなたがレート上限で強制終了されたとき、サマリーは書けません。`tasklist.md` が唯一の進捗記録になり、壊れたコミットが残る確率を下げるのが品質チェックです。**まとめ更新・まとめコミットは禁止です。**

### コミットメッセージ

件名は Conventional Commits(`feat:` / `fix:` / `docs:` / `chore:` / `refactor:` / `test:`)に従い、日本語で書きます。**本文の末尾に必ずトレーラーを付けてください。**

```
feat: ○○を追加する

- 変更点の要約

Codex-authored: true
```

件名に `[codex]` のような接頭辞を付けないでください(Conventional Commits の規約を壊します)。このトレーラーは、あなたが強制終了されて `codex-log.md` を書けなかったときに**各コミットが自分で名乗る**ための識別手段で、Claude 復帰時に `git log --grep 'Codex-authored'` で回収されます。

### 途中で判断が必要になったら

- **設計判断**: モード C ではやむを得ず下して構いません。ただし **`codex-log.md` の「設計判断」欄に、何を・なぜ・代替案を必ず書いてください**(書かないと Claude 復帰時に回収されず、設計ドキュメントと実装が食い違ったまま残ります)
- **同じエラーの修正に 2 回連続で失敗したら**、同じアプローチを繰り返さないでください。原因の仮説を書き出してから別のアプローチを取ります
- **スコープ外のことをしない**: 優先度が付いている場合は P0 以外を実装しません。要求・`design.md` に書かれていない機能を足さないでください

---

## 4. `codex-log.md` を書く(引き継ぎの単一ソース)

`.steering/[dir]/codex-log.md` に追記します。**これが Claude 復帰時の検収の入口です。**

**区切りごとに追記してください。**最後にまとめて書こうとすると、強制終了されたときに何も残りません。

```markdown
# Codex 作業ログ(縮退モード)

## [YYYY-MM-DD HH:MM]

- 対象: tasklist の N〜M 項目
- 変更: path/to/a.ts, path/to/b.ts
- コミット: abc1234, def5678
- 自己チェック: lint / typecheck / test → 全て pass
- 未検収: Claude 側の code-reviewer 未実施
- **設計判断**: [design.md に無い判断を下したら、何を・なぜ・代替案を列挙する]
- 申し送り: [その他]
```

> **`.steering/` を書き換える範囲は最小に保ってください。** Claude 側の SessionStart hook が「最新ステアリングの未完了タスク」で現在地を判定しています。ここが荒れると復帰時のオリエンテーションが壊れます。

---

## 5. やらないこと

| 項目                             | 理由                                                                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PR を作る**                    | モード C はキューとして設計されています。PR は Claude 復帰後に検収を通してから作られます                                                                                                                                                       |
| **push する**                    | ネットワーク無効です。人間が区切りごとに push します                                                                                                                                                                                           |
| **Issue 操作(ラベル・コメント)** | ネットワーク無効で `gh` も使えません。Claude 復帰時にまとめて行われます                                                                                                                                                                        |
| **force push / publish**         | 禁止です                                                                                                                                                                                                                                       |
| **新規依存の追加**               | sandbox はネットワーク無効です。取得を試みた時点で失敗します                                                                                                                                                                                   |
| **`.harness/mode` の書き換え**   | モード切替の宣言は**人間の担当**です                                                                                                                                                                                                           |
| **`.git/` 配下の改変**           | `core.hooksPath` の書き換え・`.git/hooks/` への直書きは、`.husky/` のガードレールを無効化します。`.git` への書き込み許可は**コミットを積むためだけ**に渡されています。Claude 復帰時に `check-guard-integrity.sh degraded` が機械的に検出します |
| **全体フォーマット**             | 並行編集を書き潰します(§3 参照)                                                                                                                                                                                                                |

> **`.codex/` 配下は書き込めません**(sandbox が保護しています)。この手順書自体の修正が必要になったら、直さずに人間へ報告してください。

---

## 6. 終了時の報告

作業を終えたら、次のどれかで**簡潔に**報告してください。長い差分やファイル全文を貼らないこと。

| 状態     | 書き方                                                                             |
| -------- | ---------------------------------------------------------------------------------- |
| 完了     | `完了: tasklist N/M / 変更 K ファイル / コミット K 件 / lint・型・関連テスト pass` |
| 判断待ち | `判断待ち: [何が決まっていないか] / [考えられる選択肢]`                            |
| 失敗     | `失敗: [何が起きたか] / [試したこと]`                                              |

続けて、**人間が次にやること**を 2 行で添えてください。

```
次: (1) このブランチを push してください(私はネットワーク無効で push できません)
    (2) Claude の枠が回復したら .harness/mode を normal に戻し、codex-log.md を起点に検収してください
```
