細かい指摘(破綻ではない)

記述の言い過ぎ「git merge / git pull は通す」はクリーンなマージ限定

コンフリクトしたマージを git commit で完結させる経路では pre-commit が発火し、保護ブランチ上ではブロックされる(prepare-commit-msg の merge 素通しに到達する前に止まる)。保護ブランチ上でコンフリクトする状況自体がガードで防がれているため実害はほぼ皆無だが、README・ルール類の「統合コミットは通す」はやや言い過ぎ。

同様に check-protected-branch.sh のコメント「merge 中は detached HEAD」は誤り(merge 中はブランチに留まる)。挙動には影響しない。

既知の割り切り--abort|--quit|--skip|--continue 除外がコマンド文字列全体に当たる

check-branch-policy.sh の除外正規表現はコマンド全体を見るため、コミットメッセージに --skip 等を含むと Claude 層だけすり抜ける。husky 層が拾うので多層防御としては保たれる。同ファイル冒頭が宣言する「ベストエフォート」の範囲内。

運用上の注意モード B・C の検収は当面「運用規律のみ」で支えられる

モード B・C の検収は CI 頼みだが、#1 が未決の間は「CI が赤くてもマージできる」。モード B の「draft PR を積んで後でまとめてレビュー」という規律は、機械的な強制ではなく運用規律だけで支えられる点を意識しておくこと。
