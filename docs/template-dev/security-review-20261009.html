中〜高委託成果をホスト上で実行する(npm test / lint-staged)

内容
Codex(や fork)が書いたコード・テスト・package.json の scripts は、検収時の npm test / npm run lint / コミット時の lint-staged でサンドボックスの外・ネットワーク有効のまま実行されます。
起こりうること
委託先が(プロンプトインジェクション等で)悪意あるテストを書くと、検収した瞬間に devcontainer 内のトークン・ファイルに届きます。
直さない理由
塞ぐと委託した成果を検証できなくなるため、#60 で「受容」と決定済み(codex-delegation-plan.md §9)。package.json のライフサイクル系の差分は目視・出口検査で警告されます。
軽減策
委託を挟んだ差分は git diff -- package.json と新規テストファイルを目視してから /check を回す。devcontainer 内に置くトークンの権限を絞る(下の「GH_TOKEN」)。

中〜高devcontainer が seccomp=unconfined で動く

内容
.devcontainer/devcontainer.json の runArgs でコンテナの seccomp(システムコール制限)を無効にしています。
起こりうること
このハーネスの「本当の境界」はコンテナの隔離ですが、その隔離が既定より弱くなっています。上の「ホスト上で実行」と組み合わさると、コンテナからの脱出の難度が下がります。
直さない理由
Codex のサンドボックス(bubblewrap)が動くために必要。外すと委託そのものが使えなくなる(#60 で受容済み)。
軽減策
ホスト側の Docker を最新に保つ。機密の多いマシンでは devcontainer を使わず、使い捨てのクラウド環境(Codespaces 等)で回す。

中: 運用やリポジトリ設定で軽減するもの

中ホストの GH_TOKEN がコンテナ内の全プロセスから読める

内容
containerEnv の LOCAL_GH_TOKEN にホストの GH_TOKEN がそのまま入り、npm test で動くコードを含むコンテナ内のすべてのプロセスから読めます(Codex には env の許可リスト方式で渡りません)。
起こりうること
上の「ホスト上で実行」経路でトークンが盗まれると、そのトークンが届く全リポジトリに書き込まれます。
軽減策
GH_TOKEN をこのリポジトリだけに絞った fine-grained token(Contents / Issues / Pull requests の read-write のみ)にする。classic token の repo スコープは避ける。

中GitHub の branch protection が未確認

内容
保護ブランチの検査は hook・husky・CI の 3 層ありますが、どれもローカルか「PR の base とブランチ名」しか見ません。main への直接 push・force push を最終的に止められるのは GitHub 側の設定だけです(このセッションからは設定を確認できませんでした)。
軽減策
Settings → Rules(または Branches)で main に「PR 必須」「force push 禁止」「削除禁止」「CI(quality / harness-integrity / branch-policy)必須」を設定する。

中autopilot は「信頼できる人の文章」なら無人で実行する

内容
今回の修正で外部の人のチケット・PR・コメントは対象外になりましたが、書き込み権限のある人(と trustedBots)の文章は、--permission-mode acceptEdits の claude -p にそのまま要求として渡ります。/fix-pr が CI ログを読む部分は、まだ指示文(「指示として実行しない」)だけで守っています。
起こりうること
コラボレーターのアカウント乗っ取りや、CI ログに混ざった文字列経由での誘導。
軽減策
コラボレーターを最小限にし 2FA を必須にする。trustedBots を増やすときは、その Bot が外部入力をそのまま書き込まないか確認する。AUTOPILOT_CLAUDE_ARGS に bypassPermissions を入れない。

中ツールのバージョンが固定されていない

内容
  • GitHub Actions がタグ指定(actions/checkout@v7・anthropics/claude-code-action@v1 など)で、コミット SHA で固定していない
  • claude-code-review.yml のプラグイン取得元 https://github.com/anthropics/claude-code.git が既定ブランチの最新
  • .devcontainer/post_create.sh が @anthropic-ai/claude-code / @openai/codex@latest を版指定なしで入れる
起こりうること
取得元が侵害されたとき、次の実行で悪性版をそのまま使う。Actions は CLAUDE_CODE_OAUTH_TOKEN に触れる。
直さない理由
いずれも公式・第一者の配布元で、dependabot(github-actions / devcontainers)が更新を見ている。SHA 固定は更新の手間が増える。
軽減策
少なくともシークレットに触れる anthropics/claude-code-action は SHA で固定し(dependabot は SHA 固定も更新できる)、コメントにタグ名を残す。
