# 要求: 実装ルールの欠陥修正とドキュメント整合

## 背景

fork 委譲(`20260812-fork-implementation-phase`)の導入直後に、ルール・ハーネス・ドキュメントを突き合わせた点検で欠陥が見つかった。fork 経路はまだ一度も実地で回っておらず、このまま最初のプロダクトチケットに入ると「実装が始まらない」「守りが効いていない」状態で走り出す。

## 要求

1. **fork 経路が実際に動く状態にする。** 実装 subagent が編集ツールを失う構成を解消する
2. **ステアリングディレクトリの「最新」判定を決定的にする。** 同日に複数の作業がある場合でも、hook・fork・SessionStart が同じディレクトリを指すこと
3. **テンプレート同梱の steering がプロジェクト側で悪さをしないようにする。** `<!-- main-edit-ok -->` 付きの tasklist を引き継いだまま開発を始めさせない
4. **hook の誤爆をなくす。** 危険コマンドの「文字列を含む」だけの調査コマンドがブロックされないこと
5. **`/fix-issue` にも主レビューを通す。** 3 経路のどれから入ってもレビューの手厚さが揃うこと
6. **ドキュメントを実態に合わせる。** CI のトリガー範囲・モデル ID・索引・ディレクトリ構造

## 受け入れ条件

- [ ] `implement-ticket` の frontmatter が実装に必要なツールを奪わない
- [ ] 同日に 2 つの steering ディレクトリがある状態で、最新判定が新しい方を返す
- [ ] `/kickoff` がテンプレート同梱の `.steering/` を掃除する
- [ ] `grep "gh pr create"` 相当の調査コマンドがブロックされない
- [ ] `/fix-issue` の検証ステップで `code-reviewer` が起動する
- [ ] `docs/template-dev/README.md` の索引が実ファイルと一致する
- [ ] CI(lint / 型 / フォーマット / テスト / Harness integrity)が通る
