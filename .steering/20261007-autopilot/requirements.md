# 要求: チケット消化の自動進行(autopilot)

## 背景

`/kickoff` 後は `/next-ticket` → `/clear` を人間が手で繰り返している。`/next-ticket` は
`in-progress` の Issue が 1 つでもあると「マージ待ち」で止まるため、レビュー待ちの間は
Claude が何もしない時間になる。

## 要求

1. チケットの選定 → 実装 → PR を**人手の `/next-ticket` / `/clear` なしで繰り返す**
2. **レビュー待ちの PR は待つ**(マージは人間。自動マージしない)
3. レビュー待ちの間は、**依存(`depends: #N`)が解決済みで独立に進められるチケット**を探して並行で進める
4. 同時に開いておく作業の上限(WIP)を設定ファイルで可変にする(既定 2)
5. クラウド(Claude Code on the web)とローカル CLI の**両方**で動く
   - クラウド: 司令塔セッションがチケットごとに子セッションを起動(並列・コンテナ別)
   - ローカル: `claude -p` をチケットごとに起動するループ(1 起動 = `/clear` 相当)
6. レビュー指摘・CI 失敗・コンフリクトのある PR は、新規着手より**先に**直す(マージを早めるため)

## スコープ外

- 自動マージ / 自動 approve
- コメントだけのレビュー指摘の機械検出(クラウドは PR イベント、ローカルは
  `Request changes` と `@claude` メンションで拾う)
- モード B(econ)/ C(degraded)での自動進行(枠を温存するモードと目的が矛盾する)
