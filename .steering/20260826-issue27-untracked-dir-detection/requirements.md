# 要求: 成果実在確認が未追跡ディレクトリ配下の変更を検出できない (Issue #27)

## 背景

`delegate-codex.sh` の「成果の実在確認」は `tree_snapshot()`(= `git status --porcelain | sort`)
の前後比較で作業ツリーの変化を見ている。しかし `git status --porcelain` は**新規の未追跡
ディレクトリを 1 行に畳む**:

```
?? .steering/20260826-foo/
```

このため、そのディレクトリ配下に何ファイル作ろうが追記しようが `tree_snapshot` の出力は
1 行のまま変わらない。`HEAD` も `tasklist.md` の `[x]` も動いていなければ、成果が確実に
存在するのに `status=failed` / `exit 2`(「exit 0 だが成果物が確認できない」)になる。

**フェイルオープン(素通し)ではなくフェイルクローズ側の誤検出**。正常な委託が失敗と
誤判定される経路であり、`.steering/` を新規作成してその中だけで作業する委託
(steering の初期化、新規モジュールを 1 ディレクトリにまとめて作るタスク)が該当する。

Issue #20 の検証中に実測で発見された(`.steering/20260825-issue20-codex-exit-check/verification.md` §3)。

## やること

1. `tree_snapshot()` が未追跡ディレクトリを畳まないようにする
2. 走査量の増加が実用範囲であることを実測する
3. 既存の「成果の実在確認」が退行していないこと(何も起きていない委託は引き続き `failed`)を確認する
4. 再現テスト手順を `.steering/` に記録する

## やらないこと

- 出口検査(`FORBIDDEN_PATHS`)側の変更。内容ハッシュ比較なのでこの問題の影響を受けない
- `count_done` / `HEAD` 比較のロジック変更
- 「既存の未追跡ファイルへの追記のみ」を検出する仕組みの追加(下記「既知の限界」)

## 受け入れ条件

- [ ] 新規の未追跡ディレクトリ配下にだけファイルを作る委託が `completed` / `exit 0` になる
- [ ] 何も変更しない委託が従来どおり `failed` / `exit 2` になる(退行なし)
- [ ] 大きめのワークツリーで `tree_snapshot` の所要時間が実用範囲であることを実測した
- [ ] 再現テスト手順が `.steering/` に記録されている

## 既知の限界(このチケットでは直さない)

`git status` ベースのスナップショットは**ステータス行が変わらない変更**を検出できない。
`-uall` 化で「新規未追跡ディレクトリ配下のファイル作成」は検出できるようになるが、
**既にある未追跡ファイルへの追記だけ**を行った委託は前後とも `?? path` の同一行のままで
検出できない。これは今回のスコープ外(内容ハッシュ方式への切替が必要になり、
出口検査と同じコスト構造になる)。この限界はコードのコメントとして残す。

## 制約

- `.claude/scripts/delegate-codex.sh` は**委託禁止領域**。Codex に渡さない
  (`delegate:codex` ラベルは付けない)
