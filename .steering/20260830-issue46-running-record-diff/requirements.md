# 要件: running 残置 record の検出時に禁止領域の git diff を機械確認する

- Issue: #46(P2 / `delegate:codex` なし = 対象が `delegate-codex.sh` 自身のため委託禁止領域)
- ブランチ: `feature/issue46-running-record-diff`

## 背景

出口検査(禁止領域の内容ハッシュ前後比較)には空振り条件がある: **SIGINT / SIGTERM で `codex exec` の途中に死ぬと出口検査に到達しない。**

1. 委託先が禁止領域を書き換えた状態で委託が中断される
2. run record は `status=running` のまま残る
3. **次回委託の BEFORE スナップショットが、改ざん後の状態を基準に取る**
4. 以後その改ざんは恒久的に検出不能になる

現在の手当は入口検査5-5 の警告分岐(`§12.6` への誘導)だけで、**人間が読み飛ばすと検出機会が失われる**。禁止領域の汎用項目はほぼすべて git 追跡ファイルなので機械的に確認できる。

## スコープ(やること)

1. 入口検査5-5 で `running` のまま残った record を検出したとき、禁止領域を `git diff HEAD -- <paths>` で機械確認する
2. dirty だった場合の倒し方を決める(設計判断 → `design.md` §2)
3. 検出時のメッセージに、確認すべきファイルと回復手順への導線を含める

## スコープ外(やらないこと)

- run record の自動削除・自動 accept(未検収 record = 検収キューの意味づけを維持する)
- SIGINT ハンドラで出口検査を走らせること(`trap` での検査は中断タイミング次第で不完全になり、「検査が走った」記録だけが残る方が危険)
- git 追跡外の禁止領域(`.harness/mode` / `.harness/codex-runs/`)の検査。`.gitignore` 対象で `git diff` に出ない — 対象外である旨をコメントに明記する

## 受け入れ条件

- [ ] `running` の record があっても禁止領域が clean なら従来どおりの警告のみ
- [ ] 司令塔が禁止領域を正当に編集している最中の誤爆条件が文書化されている
- [ ] git 追跡外の禁止領域が検査対象外である旨がコメントにある
