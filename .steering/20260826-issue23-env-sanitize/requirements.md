# 要求: 委託先へ渡る機密の境界を明確にする(Issue #23)

## 背景

`delegate-codex.sh` は `codex exec` を**親プロセスの環境変数をそのまま継承して**起動している。
Codex の sandbox には読み取りの除外機能が無い(計画 §13 #7)ため、委託先は環境変数もワークツリー外のファイルも読める。

実測(devcontainer, 2026-08-26)で、親の環境に以下の資格情報系が乗っていることを確認した:

- `LOCAL_GH_TOKEN` — gh CLI のトークン
- `CLAUDE_CODE_MESSAGING_TOKEN` / `CLAUDE_CODE_MESSAGING_SOCKET` — Claude Code の IPC 資格情報

入口検査1(denylist)は `find .` でリポジトリ内しか走査しないため、**これらは検査対象にすらならない**。
にもかかわらず `codex-denylist.txt` 冒頭は「ここが唯一の層」と書いており、保護範囲を過大に見せている。

## 要求

1. **R1**: `codex exec` の起動環境を許可リスト方式にし、許可されていない変数を子プロセスへ渡さない
2. **R2**: 許可リストは実測で確定させる(推測で削って委託が丸ごと動かなくなることを避ける)
3. **R3**: `codex-denylist.txt` / 計画 §10.2 の保護範囲の記述を実態(= ワークツリー内のみ)と一致させる
4. **R4**: `CODEX_DELEGATE_ACK_SECRETS` を「人間確認が唯一の層」と書いている箇所を実態(= 承認付き再実行)に改める

## 受け入れ条件(Issue より)

- [ ] 環境変数をサニタイズした状態で impl / explore / review の 3 モードが正常に完走する
- [ ] `gh` のトークン等が子プロセスの環境に渡っていないことを確認した
- [ ] `codex-denylist.txt` と計画 §10.2 の記述が実際の保護範囲(ワークツリー内のみ)と一致している
- [ ] ACK 承認まわりのコメントが実態(承認付き再実行)と一致している

## スコープ外

- `ACK` 値を「検出ファイル一覧のハッシュ」にする強化
- ホーム配下を物理的に隔離する仕組み(別コンテナ・別ユーザー実行)

## 委託可否

**Codex に委託しない。** 対象の `delegate-codex.sh` / `.claude/codex-denylist.txt` はいずれも
`CLAUDE.md`「プロジェクト固有ルール」の委託禁止領域。`delegate:codex` ラベルは付いていない。
