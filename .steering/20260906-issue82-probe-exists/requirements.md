# 要求: 検証プローブのホスト実行経路を閉じる(Issue #82)

## 背景

入口検査3 は `AGENTS.md` の `<!-- verify-probe: ... -->` を許可形式で検査したうえで、
`env -i ... bash -c "$PROBE"` として**ホスト上で実行**する。テンプレート既定のマーカーは

```
<!-- verify-probe: npx --no-install eslint --version -->
```

で、これは `node_modules/.bin/eslint` を解決して実行する。`node_modules/` はワークツリー内
なので `workspace-write` の委託先が書き換えられ、その改変は**次回の委託の入口検査でホスト実行
される**(sandbox 内で書く → 次回起動で sandbox 外実行)。`env -i` は環境変数を絞るだけで
ネットワークは塞がない。

問題は経路の存在そのものではなく、**代償措置が実在しないこと**。`delegate-codex.sh:497-503`
のコメントは「ワークツリーの完全性は出口ハッシュ検査・`check-guard-integrity.sh degraded` が
受け持つ別の層」と書いているが:

- 出口ハッシュ検査は `FORBIDDEN_PATHS` に列挙されたパスだけを走査し、`node_modules/` は入っていない
- `degraded` 検査は `git log` 起点で、`node_modules/` は gitignore 済み

つまり**前提だけが記述されていて、その層は存在しない**。#80(`.husky/_` / `settings.local.json`)
と同じ「gitignore 済みだがホストが実行する経路」の系統。

## 要求

| ID | 要求 |
| --- | --- |
| R1 | プローブの既定形式から**ホスト上のプロセス起動を無くす**。マーカーが表す「依存が入っているか」の確認を、exec ではなく存在確認で満たす |
| R2 | 新形式のパス指定で**パストラバーサル・絶対パス**が形式検査で落ちる |
| R3 | 既存の P1 / P2 / P3 形式は**後方互換として残す**(他スタックのプロジェクトが依存している) |
| R4 | `delegate-codex.sh` のコメントから、**実在しない代償措置への言及を消す**。塞げていないものを塞げていると書かない(#60 で決めた「受容するなら明文化する」と同じ姿勢) |
| R5 | `AGENTS.md` §2 の形式制約の説明を、採用した形式に合わせて更新する。テンプレート既定のマーカーを新形式に切り替える |
| R6 | 形式外・未設定時のフェイルオープン(警告 + スキップで委託は続行)を変えない。導通確認が壊れても業務は止めない(#43 の教訓 3) |

## スコープ外

- `node_modules/` を禁止領域に入れること(数万ファイルのハッシュで現実的でない)
- 既存 P1 / P2 / P3 形式の削除
- プローブを sandbox 内で実行する仕組みの構築(`codex exec` の起動コストが入口検査に乗る。別チケット規模)
- `PROBE_ALLOWED_CMDS` の変更(実測に基づく現状の選定は妥当)

## 受け入れ条件

- [ ] 採用した方式が `design.md` に判断として記録されている
- [ ] `exists` 形式のプローブが**ホスト上で 1 つもプロセスを起動せずに**判定できる
- [ ] `exists ../../etc/passwd` / `exists /etc/passwd` のようなパストラバーサル・絶対パスが形式検査で落ちる
- [ ] `delegate-codex.sh` のコメントから、実在しない代償措置への言及が消えている
- [ ] `AGENTS.md` §2 の説明が実装と一致している
- [ ] 既存の P1〜P3 形式のプローブが従来どおり通る(後方互換の確認)
- [ ] `docs/template-dev/CHANGELOG.md` に追記済み
