# 要求: verify-probe のホスト実行に形式検査と環境遮断を入れる

- Issue: #43(P1 / `ticket`)
- 根拠: Codex 併用ハーネス実装レビュー(2026-08-29)S-4

## 背景

入口検査3(`.claude/scripts/delegate-codex.sh`)は、`AGENTS.md` の
`<!-- verify-probe: ... -->` から抽出した文字列を **そのままホスト上の `bash -c`
に渡して実行する**。`AGENTS.md` は出口ハッシュ検査と委託禁止領域で守られているが、
次の 3 経路では検査が効かない:

1. モード C(縮退)経由 — `delegate-codex.sh` を通らない
2. SIGINT / SIGTERM で出口検査に到達せず死んだ委託 — 次回の BEFORE スナップショットが
   改ざん後を基準に取るため、以後恒久的に検出不能になる
3. 人間の誤マージ・手動編集

結果として「サンドボックス内で 1 行書く → 次回の委託起動でホスト上で実行される」という
**サンドボックス外へのコマンド実行経路**が成立し得る。現状この経路に対する形式検査は無い。

さらに、プローブは**親の環境をそのまま継承して実行される**。親には `LOCAL_GH_TOKEN` /
`CLAUDE_CODE_MESSAGING_TOKEN` 等が乗っており、#23 で `codex exec` 側には許可リスト方式の
`env -i` を入れたが、プローブ実行は素通しのままだった。

## 要求

| # | 要求 | 受け入れ条件(Issue 由来) |
| --- | --- | --- |
| R1 | プローブの形式を許可リストで制限し、外れたら**実行せず警告してスキップ**する | 形式外のプローブ(`curl ...` / `; rm -rf ...` 等)が実行されず警告が出る |
| R2 | 現行の正当なプローブはそのまま通る | `npx --no-install eslint --version` が従来どおり実行され成功する |
| R3 | 実行前にプローブ内容を必ず stderr に出す | 失敗時のみでなく毎回出る |
| R4 | `env -i` + 許可リストで実行し、環境変数への到達を断つ | `env -i` 下でも現行プローブが成功する(PATH の受け渡しを実測) |
| R5 | 形式制約を `AGENTS.md` の説明コメントに明記する | 委託先が守るべき形が読める |
| R6 | 記録を更新する | `CLAUDE.md` の該当記述を更新 / `docs/template-dev/CHANGELOG.md` に追記 |

## スコープ外

- プローブの廃止(ネットワーク無効 sandbox 前の導通確認として価値がある)
- `AGENTS.md` を禁止領域から外すこと / `verify-probe` の置き場所変更(**多層防御であって置き換えではない**)
- 許可リストのプロジェクト別設定化(まず固定運用し、外れるケースが出てから考える)

## 失敗の倒し方

形式外・実行不能は **フェイルオープン(警告 + スキップ)** とする。R1 が守るのは
「ホスト上で任意コマンドが走らないこと」であり、導通確認が取れないこと自体は
委託を止める理由にならない(現行の「マーカー不在時はスキップ」と同じ倒し方)。
プローブが**実行されて失敗した**場合のみ従来どおり `exit 3` を維持する。
