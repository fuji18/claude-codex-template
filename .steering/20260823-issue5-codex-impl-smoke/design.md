# 設計書: §12.7 入口検査のランブック追加

<!-- status: ready -->

## 対象ファイル

`docs/template-dev/codex-delegation-plan.md` のみ。他のファイルを触らないこと。

## 挿入位置

`### 12.6 委託が途中で止まったとき(Codex 側のレート上限など)` の節が終わった直後、
次の `---` 区切り(`## 13. 未確認の前提` の手前)の**前**に、`### 12.7 委託が入口で止まったとき(exit 2 / 3 / 5)` として挿入する。

## 書く内容

冒頭に 1〜2 行のリード文を置く。趣旨は「入口検査は**枠を消費する前に**止めるための層であり、
止まったこと自体は失敗ではない。終了コードで復旧手段が決まる」。

続けて次の表を置く。列は `検査` / `終了コード` / `何が起きているか` / `復旧手順` / `この検査が空振りする条件` の 5 列。
行は以下の 6 つ。内容は `.claude/scripts/delegate-codex.sh` の該当ブロックのコメントを根拠にすること
(推測で書かない。スクリプトを読んで確認する)。

1. 入口検査1(機密ファイル)
2. 入口検査2・3(AGENTS.md / 検証プローブ)
3. 入口検査5-1(target がステアリングディレクトリでない)
4. 入口検査5-2(`design.md` の完成マーカーが `draft`)
5. 入口検査5-3(`core.hooksPath` が未設定または実在しない)
6. 入口検査5-4(保護ブランチ上)

表の下に、再入防止(5-5)についての段落を 1 つ置く。含める点:

- 同じステアリングへの委託が**実行中**なら `exit 2` で止まる
- `status=running` なのにプロセスが居ない record は**警告を出して通す**(強制終了の疑い)。その場合の根拠は
  サマリーではなく `tasklist.md` と `git diff`(§12.6 へ誘導する)
- record の状態を実態に合わせる手段は `bash .claude/scripts/codex-run.sh set-status <id> <status>`
