# 要件: 出口検査に `/kickoff` 由来のプロジェクト固有パスを含める(Issue #28)

## 背景

#20 で入れた出口検査は `delegate-codex.sh` 内の `FORBIDDEN_PATHS` 配列だけを見る。この配列に入っているのは**テンプレート由来の汎用項目**のみで、`/kickoff` フェーズ4 が `AGENTS.md` §4 のマーカー内へ追記する**プロジェクト固有パス**(認証・決済・データ移行など)は機械的に守られていない。テンプレート自身は project 固有パスを持たないため表面化しないが、`/kickoff` を通った下流のプロジェクトでは初日からこの状態になる。

## スコープ

1. 委託開始前に `AGENTS.md` のマーカー(`<!-- kickoff:delegation-forbidden-paths -->` 〜 `<!-- /kickoff:delegation-forbidden-paths -->`)内からバックティック囲みの文字列を抽出し、出口検査の対象に加える
2. スクリプト内の汎用項目(`FORBIDDEN_PATHS`)と抽出分をマージする。**汎用項目は必ず残る**
3. 散文(`AGENTS.md` / `CLAUDE.md`、及び整合のため `.claude/commands/kickoff.md` 1 行)を実装に合わせる

## スコープ外

- 3 箇所目のリストファイル(`.claude/codex-forbidden-paths.txt` 等)の新設 — #20 の判断を覆さない
- `/kickoff` フェーズ4 の追記フォーマットの変更 — 現行の「箇条書き + バックティック」のまま扱えるようにする
- 入口検査・denylist 層への変更

## 受け入れ条件(Issue #28 より)

- [ ] マーカー内にダミーのプロジェクト固有パスを追記した状態で、そのパスを改ざんした委託が `failed` / `exit 2` になる
- [ ] マーカーが存在しない `AGENTS.md` でも汎用項目の検査が従来どおり働く
- [ ] マーカー内をすべて削除しても汎用項目の保護が消えない
- [ ] 説明用の語がバックティックで囲まれていても誤検出しない(実在しないパスは無視される)
- [ ] 委託中にマーカー内を書き換えても、その回の検査対象は開始時点のリストのまま(かつ `AGENTS.md` 自身の改ざんとして検出される)
- [ ] `CLAUDE.md` / `AGENTS.md` の記述が実装と一致している
- [ ] 再現テスト手順が `.steering/` に記録されている

## 制約

- **委託禁止領域のチケット**(`delegate-codex.sh` / `AGENTS.md`)。Codex に委託しない。`implement-ticket` の fork が実装する
- テスト中の巻き戻しに `git checkout -- <path>` を使わない(#15・#20 で事故発生)。`cp` でバックアップ/リストアする
