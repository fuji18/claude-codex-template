# 要求: 実装フェーズの fork 委譲と rules の役割分割

## 背景

実装フェーズを Sonnet で回すために、これまでは手動で `/clear` → `/model sonnet` → 完了後 `/model opus` と切り替える運用だった。この切替は毎チケット発生して手間が大きく、かつ**忘れると全額 Opus 単価**という失敗モードを持つ(切替前の `/clear` を忘れると、膨らんだコンテキスト全体がキャッシュミスになる)。

## 要求

1. **モデル切替を人手から外す。** 実装フェーズが自動的に Sonnet で走り、司令塔は Opus のまま維持されること
2. **忘れようがない構造にする。** 命令(コマンド定義)だけに頼らず、逸脱を機械的に検知・ブロックする層を持つこと
3. **サブエージェントに載るコンテキストを削る。** `.claude/rules/*.md`(10,286 文字)は現状 `code-reviewer` / `test-runner` 等を spawn するたび全量ロードされている。司令塔だけが使うルールを分離すること
4. **既存の 3 経路すべてに適用する。** `/next-ticket` / `/add-feature` / `/fix-issue` のいずれから入っても同じ委譲経路を通ること

## 制約(調査で確定した事実)

- カスタムサブエージェントは CLAUDE.md と `@` インポートを必ず読み込む。**エージェント単位で除外する設定は存在しない**(除外されるのは組み込みの Explore / Plan のみ)
- スキルの `model:` frontmatter による上書きは**そのターンの間だけ**有効で、次のプロンプトでセッションのモデルに戻る
- `context: fork` + `model:` はフォークされたサブエージェントのモデルを設定できる。`background: false` にしないとツールセットが狭まり、編集がチェックポイント(`/rewind`)の対象外になる
- フックはサブエージェント内でも発火し、入力 JSON に `agent_id` / `agent_type` が載る(メインスレッド由来には `agent_id` が無い)
- `SessionStart` フックはメインセッションでのみ発火し、`additionalContext` を注入できる。`SubagentStart` は context 注入不可

## 受け入れ条件

- [ ] `/next-ticket` 実行時、ユーザーがモデルを切り替えずに実装が Sonnet で走る(**未検証**。最初のプロダクトチケットで実地確認する。申し送り参照)
- [x] 司令塔が実装フェーズ中にコードを直接編集しようとするとブロックされる
- [x] サブエージェントに載る共通ルールが 4,000 文字程度まで削減される(`spec-driven.md` 3,402 文字)
- [x] 司令塔向けルールはメインセッションでのみ読み込まれる
- [x] README / CLAUDE.md / CHANGELOG が新構成と整合している
