# 検証記録・振り返り: rec_field() の二重実装を共有ファイルに集約する(Issue #45)

## 1. 計画時に確定させたこと(司令塔)

計画フェーズで**設計判断をすべて潰してから**実装に渡した。design.md §0 に置いた「実装者が
再調査しなくてよい事実」が要点で、特に効いたのは次の 1 点:

> `ROOT` と `EX_FAIL` は入口検査より**前**(91 行 / 86 行)で確定している。

これが分かっていたので、`source` を旧 `rec_field` の位置(642 行 = 入口検査4 の後)ではなく
`cd "$ROOT"` の直後に置けた。結果として:

- **`--print-forbidden` を含む全起動経路**が共有ファイルの解決を通る
- 検証が **codex CLI にも機密承認にも依存しない**経路だけで組める(§3)

旧 `rec_field` の位置にそのまま置いていたら、codex CLI が無い環境では解決が一度も走らず、
壊れていても気づけないまま緑になっていた。

## 2. 自己コピー exec との整合(このチケットの本題)

`delegate-codex.sh` は起動直後に自身を一時ディレクトリへコピーして exec する(#15)。
共有ファイルを `$ROOT` から素朴に `source` すると、**「実行中に委託先が書き換えられるファイル」が
1 本増える** = この保護に穴が開く。

採った対策は **「コピー先へ `lib-record.sh` も一緒に運び、自身の隣から source する」**(design §1 案 A)。
検討して却下した案は 3 つ:

| 案 | 却下理由 |
| --- | --- |
| B: コピー時に本文を埋め込む | コピー処理が「運ぶ」から「合成する」に変わり失敗モードが増える。得るものは A と同じ |
| C: 実行前後でハッシュ照合 | **検知しかできない**。A は発生自体を防ぐ |
| D: `$ROOT` から素朴に source | #15 の保護に穴を開ける。委託先がハーネス層を触るのはテンプレート開発では常態 |

**フェイルの向きを 2 箇所で違えた**点が設計の勘所:

- **コピー失敗はフェイルオープン**(委託を止めない)。自己コピーは堅牢化の層であって安全検査ではない、
  という #15 の既存判断と揃えた。ただし `$ROOT` へフォールバックしたことは警告に出す
- **共有ファイルが 1 つも無い場合はフェイルクローズ**。`rec_field` は入口検査5-5(impl の再入防止)が
  使う。未定義のまま進むと空文字列が返って**検査が静かに素通しする**だけで、失敗として現れない。
  これはこのチケットが集約しようとしている「jq 不在時のフェイルオープン」と同じ穴の別形

## 5. 申し送り

- **`--print-forbidden` の出力行数**: `FORBIDDEN_PATHS` 単体では 10 行だが、`AGENTS.md` §4 由来の
  `PROJECT_FORBIDDEN_PATHS`(#28)を含めた総出力は 22 行。design.md §7 が「10 行」と書いたのは前者の意。
  今後この経路の行数を検証条件に使うときは、どちらを指しているかを明示すること
- **jq 経路と sed 経路には既存の出力差がある**(design §6)。`codex-run.sh pending` のサマリー行で、
  `jq -r` は JSON 中の `\n` を実際の改行に戻すが sed 経路は生の 2 文字 `\n` を返す。
  **今回入れた差ではなく、現行 2 実装が最初から持っていた差**。したがって等価性検査は
  「jq 経路 vs sed 経路」ではなく**変更前の同じ経路との比較**で行った。直すなら run record の
  書式に手を入れる別チケットになる
- **`check-guard-integrity.sh` は変更していない**。`FORBIDDEN_PATHS` が `.claude/scripts/` を
  ディレクトリ単位で持つ(#40)ため、`lib-record.sh` は追加作業なしで出口検査・縮退検査の対象になる。
  個別に足すと #40 が畳んだ「ファイルが増えるたびに列挙が漏れる」問題を再導入する。
  同じ理由で `AGENTS.md` §4 と `CLAUDE.md` の禁止領域リストも変更不要
- **副次的な良い性質**: `lib-record.sh` が消えると `--print-forbidden` が空を返し、
  `check-guard-integrity.sh` が「委託禁止領域を返さない」と鳴る。**フェイルクローズが検知層まで
  貫通する**。意図した挙動なので、将来この経路を静かにフェイルオープンへ倒さないこと
- 途中でセッション上限により検収サブエージェント 2 本が中断したが、作業ツリーは無傷で、
  同じ内容で起動し直して完走した。**実装成果は `.steering/` と作業ツリーに残るため再開に支障はない**
