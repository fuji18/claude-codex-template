# ドキュメントと実装の同期

実装コードと `docs/` の永続ドキュメントを突き合わせ、乖離（ドキュメントに書かれていない実装・実装と異なる記述）を検出して更新するコマンドです。機能追加が数回積み重なったタイミングでの実行を推奨します。

**引数:** なし（任意で対象ドキュメントを絞ってよい。例: `/sync-docs architecture`）

**実行方式:** 読むファイル量が多い乖離検出（ステップ1〜2）は読み取り専用の subagent（Sonnet）に委譲し、司令塔は乖離リストだけを受け取る。更新の判断と実施（ステップ3〜4）は司令塔が担う。

---

## 手順

### ステップ1〜2: 乖離検出の委譲

Agent ツールで調査用 subagent（`general-purpose`、model: sonnet）を起動し、以下を依頼する:

1. `docs/` の永続ドキュメントを全て読む（引数で対象が指定されている場合はそのドキュメントを中心に読む）。
2. `.steering/` の各ディレクトリの `tasklist.md` から、直近の実装作業の履歴を把握する。
3. 実装コード（`src/` 等）の構造を確認する。
4. 下表の観点で乖離を洗い出し、**乖離リストのみ**（ドキュメントの記述 ⇔ 実装の実態、各項目の該当ファイル）を返す。ファイル全文の引用は返さない。**編集は一切しない**よう明示する。

| ドキュメント | 確認する観点 |
|---|---|
| product-requirements.md | 実装済み機能がPRDに反映されているか。スコープ外になった機能が残っていないか |
| functional-design.md | 機能の振る舞い・画面・APIの記述が実装と一致するか |
| architecture.md | 技術スタック・依存関係・構成が実態と一致するか |
| repository-structure.md | ディレクトリ構造の記述が実態と一致するか |
| development-guidelines.md | 規約と実際のコードスタイルが一致するか |
| glossary.md | コード内の主要な概念・命名が用語集に登録されているか |

### ステップ3: 乖離レポートの提示

検出した乖離を以下の形式で提示する。

```
## 乖離レポート

### [ドキュメント名]
- **乖離内容:** [ドキュメントの記述] ⇔ [実装の実態]
- **推奨対応:** ドキュメント更新 / 実装修正 / 要判断
```

- 乖離がゼロの場合は「乖離はありません」と報告して終了する。
- **実装のほうが間違っている可能性がある乖離**（設計意図に反する実装）は、ドキュメントを書き換えるのではなく要判断としてユーザーに提示する。

### ステップ4: ドキュメントの更新

1. 「ドキュメント更新」と判断した項目について、該当ドキュメントを更新する。
2. 更新は事実の反映に留め、設計方針の変更に踏み込む場合は必ずユーザーに確認する。
3. 更新したドキュメントと変更概要を一覧で報告する。
