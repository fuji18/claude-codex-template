# 中断した作業の再開

`.steering/` ディレクトリをスキャンして未完了のタスクリストを検出し、中断していた作業を再開するコマンドです。セッションをまたいで作業を続けるときに使用します。

**引数:** なし（任意でステアリングディレクトリ名を指定してよい。例: `/resume-work 20260711-user-profile`）

---

## 手順

### ステップ1: 未完了作業の検出

1. `.steering/*/tasklist.md` を全て検索し、未完了タスク（`- [ ]`）を含むものを特定する:
   ```bash
   grep -l "^\s*- \[ \]" .steering/*/tasklist.md
   ```
2. 検出結果に応じて分岐する:
   - **0件:** 「未完了の作業はありません」と報告して終了する。
   - **1件:** そのまま次のステップに進む。
   - **複数件:** 各作業の名前・未完了タスク数・最終更新日時を一覧表示し、どれを再開するかユーザーに確認する。

### ステップ2: コンテキストの復元

再開する作業について以下を読み込み、状況を把握する。

1. 対象ディレクトリの `requirements.md`・`design.md`・`tasklist.md`
2. `tasklist.md` の完了済みタスク（`[x]`）と申し送り事項から、どこまで進んでいたかを把握する
3. `git status` と `git log --oneline -10` で、コミット状況と作業ブランチを確認する
   - 対応するフィーチャーブランチが存在する場合は、そのブランチにチェックアウトする
4. 完了済みタスクに対応する実装が実際に存在するかを軽く検証する（tasklist.mdと実態がずれている場合は、tasklist.mdを実態に合わせて修正してから再開する）

### ステップ3: 再開内容の報告

作業を再開する前に、以下を簡潔にユーザーへ報告する。

```
## 再開する作業: [作業名]
- 進捗: [完了数] / [全タスク数]
- 次のタスク: [先頭の未完了タスク]
- ブランチ: [ブランチ名]
```

### ステップ4: 実装の再開(implement-ticket への委譲)

1. `git status` で作業ツリーがクリーンであることを確認する(未コミットの変更があれば先にコミットする)。
2. `Skill('implement-ticket')` に対象のステアリングディレクトリを渡して実行する。**司令塔は実装コードを書かない**(`tasklist.md` の進捗は保存されているため、fork が続きから再開する)。
3. 戻り値が `判断待ち` / `失敗` の場合は、判断を `design.md` に追記してから再実行する(分岐の詳細は `/add-feature` ステップ5)。
4. `完了` が返ったら `/check` を通し、`Skill('steering')` の**振り返りモード**で申し送り事項を記載する。
