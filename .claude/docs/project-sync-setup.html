Project 導入 操作手順書

すでに開発が進んでいるリポジトリに GitHub Projects の board を後から足すための、画面とボタンまで書いた手順。しくみの説明は .claude/docs/project-sync-guide.html にある。この手順書は「どこを押すか」だけを扱う。

何のためにやるのか

チケットの状態は Issue のラベルと PR にすでに入っている。ただしそれを一覧で見る場所が無い —— いま何本が手つかずで、何本がレビュー待ちで、どこで詰まっているのかを知るには、Issues を絞り込み直して数えるしかない。 board はその一覧を勝手に最新に保ってくれる 1 枚になる。

board は見るだけのもの。 カードを動かしても開発は進まないし、止まりもしない。チケットの状態を決めているのは今までどおり Issue のラベルと PR で、board はそれを映しているだけ。だから失敗しても壊れるものが無い —— 列がずれたら同期をもう一度流せば直る。

入れないと困るものではない。チケットが 10 本を超えたあたりから効いてくる類のもので、それ以下なら Issues の一覧で足りる。

必要なもの

この作業で触る 3 つの画面

ここが一番こんがらがる。GitHub の設定画面は「あなた個人の設定」と「リポジトリの設定」が別物で、見た目がよく似ている。 さらに Project にも独自の設定画面がある。下の図の 3 か所を行き来する。

「Settings」が 2 つあることに注意。 画面右上のアイコンから入る Settings はあなた個人の設定で、トークンはここで作る。リポジトリのページにある Settings タブはそのリポジトリの設定で、トークンはここに登録する。登録先を間違えても動かないので、図 1 の矢印の向きを確かめながら進める。

1. ファイルを取り込む

対象のリポジトリを開いて Claude Code で次を実行する。このテンプレートから作ったプロジェクトなら、これだけでスクリプトとワークフローが入る。 

/sync-template

入ったか確かめる。4 つとも表示されれば取り込めている。

ls .claude/scripts/project-sync.sh .claude/project-sync.json .github/workflows/project-sync.yml .claude/docs/project-sync-guide.html
テンプレート外のリポジトリに入れる場合。 上の 4 ファイルをこのテンプレートからコピーし、.github/workflows/ci.yml に Test project sync ステップを足す。ただしチケットを ticket ラベルで管理していることが前提になる —— 別のラベル名なら手順 5 で読み替える。
取り込んだら既定ブランチ(ふつうは main)までマージしておく。 GitHub は既定ブランチにあるワークフローしか手動実行のボタンを出さない。作業ブランチに置いたままだと、手順 6 で Run workflow が見つからず詰まる。

2. Project を作る

  1. github.com の右上のアイコンをクリック → メニューの Your projects を選ぶ
  2. 右上の緑の New project ボタンを押す
  3. テンプレートの一覧が出る。左から Board を選び、名前を入れて Create project を押す
    Board を選ぶ理由。 Status フィールドが最初から付いてくるので、作り直す手間が減る。Table でもあとで同じ形にできるが、列を手で足すことになる。
  4. 列を 4 つにする。Board の既定は Todo / In Progress / Done の 3 つで、 In Review が足りない。board の右端にある +(列の追加)を押して In Review を作り、In Progress と Done の間にドラッグする
    並び順は見た目だけの話。 同期は列の名前だけを見るので、順番が違っても動く。ただし board を左から右に読んだときに開発の流れと一致していないと、一覧として読みにくくなる。
  5. (任意)優先度の列を足す。右上の ⋯ → Settings → 左の Fields → New field。名前を Priority、種類を Single select にして、選択肢に P0 P1 P2 を作る。作らなくても動く(優先度を反映しないだけ)
  6. URL を控える。board を開いた状態でブラウザのアドレス欄をコピーする。次のどちらかの形になっている 
    https://github.com/users/<あなたのログイン名>/projects/3
https://github.com/orgs/<組織名>/projects/3
    末尾に /views/1 などが付いていたら、それは消してよい。

3. トークンを作る

ここだけは代わりにやってもらえない。 トークンはあなたのアカウントそのものの鍵なので、人にも AI にも渡さず自分で作って自分で貼る。board の更新履歴はこの鍵の持ち主の名前で残る。

なぜ必要か —— GitHub Actions が最初から持っている GITHUB_TOKEN は Projects にアクセスできない(GitHub の仕様として明記されている)。だから別の鍵を用意する。

  1. 右上のアイコン → Settings(リポジトリの Settings タブではない。図 1 の左の箱)
  2. 左の一覧をいちばん下までスクロールして Developer settings を押す
  3. Personal access tokens → Tokens (classic) を開く
  4. Generate new token → Generate new token (classic) を選ぶ
    fine-grained ではなく classic を選ぶ。 fine-grained でも動く可能性はあるが、GitHub の文書が Projects 用の権限名を示していないため、確実な classic を案内している。
  5. Note に用途がわかる名前を入れる(例: project-sync)。Expiration は期限で、切れると同期が止まる。90 日か No expiration を選ぶ
  6. 権限に 2 つチェックを入れる。いちばん上の repo(親にチェックすれば配下もすべて入る)と、 下のほうにある project
  7. いちばん下の Generate token を押す
  8. 表示された文字列をコピーする。画面を離れると二度と見られない。手順 4 をこのまま続けてすぐ貼るのがいちばん安全
この文字列をファイルやチャットに貼らない。 コミットすると GitHub が検知して無効化する(そして作り直しになる)。貼る先は次の手順 4 の入力欄だけ。

4. リポジトリに登録する

ここからは対象のリポジトリのページでの作業(図 1 の真ん中の箱)。

4-1. トークンを登録する

  1. リポジトリのページ上部の Settings タブを押す
  2. 左の一覧から Secrets and variables → Actions を開く
  3. Secrets タブが選ばれていることを確かめ、緑の New repository secret を押す
  4. Name に次をそのまま入れる(綴りが 1 文字でも違うと動かない) 
    PROJECT_SYNC_TOKEN
  5. Secret に手順 3 でコピーした文字列を貼り、Add secret を押す

4-2. board の URL を登録する

  1. 同じ画面の上部で Variables タブに切り替える(Secrets の隣)
  2. New repository variable を押す
  3. Name に次を入れる 
    PROJECT_URL
  4. Value に手順 2 で控えた URL を貼り、Add variable を押す
URL は秘密ではない。 Variables に入れるのはそのため(Secrets と違ってあとから中身を確認できるので、打ち間違いを追える)。リポジトリに固定でよければ .claude/project-sync.json の projectUrl に書いてコミットしてもよい。

5. 列名を合わせる(必要なときだけ)

board の列名を既定どおり(Todo / In Progress / In Review / Done)にしたならこの手順は飛ばす。日本語にした場合や、別の呼び方をしている場合だけ読む。

.claude/project-sync.json を開き、実際の列名を候補に足す。配列の先頭から順に、大小文字と前後の空白を無視して照合し、最初に見つかったものを使う。 

"status": {
  "todo": ["Todo", "To do", "未着手"],
  "inProgress": ["In Progress", "In progress", "進行中"],
  "inReview": ["In Review", "In review", "レビュー中"],
  "done": ["Done", "完了"]
}

ラベル名が違う場合も同じファイルで直す。

"ticketLabel": "ticket",
"inProgressLabel": "in-progress"
見つからない列は、その 1 項目だけ飛ばす。 In Review を作らなかった board でも、残りの 3 列はふつうに動く。例外は Status フィールドそのもの —— これが見つからないときは board の指定を間違えているので、エラーで止まる。

6. 実行する

  1. リポジトリの Actions タブを押す
  2. 左の一覧から Project Sync を選ぶ
  3. 右側の Run workflow を押すと小さなパネルが開く
  4. 「closed の Issue も board に投入する」にチェックを入れる。進行中のプロジェクトではここが肝
  5. パネル下部の緑の Run workflow を押す
  6. 数秒で一覧に実行が現れる。クリックして緑のチェックが付くまで待つ(チケット数にもよるが 1 〜 3 分)

チェックを入れるかどうかで、board の見え方はこれだけ変わる。

7. 確認する

board を開く。チケットがカードとして並んでいれば成功。

手元に gh と jq があるなら、board に書き込まずに対応関係だけを表示できる。設定を直したあとの確認はこれがいちばん速い。 

bash .claude/scripts/project-sync.sh --check

うまくいっているときは、列ごとの対応がこう出る。

project-sync.sh: Status フィールド: Status
project-sync.sh:   todo → Todo
project-sync.sh:   inProgress → In Progress
project-sync.sh:   inReview → In Review
project-sync.sh:   done → Done

対応する列が無い と出た行が、board に足りない列。手順 2 に戻って作るか、手順 5 で実際の名前を候補に足す。

つまずき表

症状 原因 直し方
Actions に Run workflow ボタンが無い ワークフローが既定ブランチに入っていない 手順 1 の変更を main までマージする
実行はされたが board が空 ticket ラベルの付いた Issue が無い Issues でラベルを確かめる。別のラベル名なら手順 5
終わったチケットが Done に無い 初回投入でチェックを入れ忘れた 手順 6 をチェックありでもう一度流す
着手中のはずが Todo にある in-progress ラベルが付いていない Issue にラベルを足す。次の同期で動く
ログに「Project 同期は無効」とだけ出る PROJECT_SYNC_TOKEN が読めていない 手順 4-1 の綴りを確かめる。Variables 側に入れていないかも見る
赤くなり project が見つからない URL の形が違う / トークンに project 権限が無い 手順 2 の URL 形式と、手順 3 のチェック 2 つを見直す
ある日から急に赤くなった トークンの期限切れ 手順 3 で作り直し、手順 4-1 で上書きする
組織の Project に書けない classic PAT では権限が足りないことがある 組織の設定で PAT を許可するか、GitHub App を使う

入れたあと

もう何もしなくてよい。以降は次のときに board が勝手に動く。

あなたがすること board の動き
/setup-tickets でチケットを起こす Todo に並ぶ
/next-ticket で着手する In Progress に動く
PR を作る In Review に動く(draft でも)
PR をマージする Done に動く
カードを手で動かしてしまっても問題ない。 次にその Issue に何か起きた時点で、ラベルと PR から決め直した位置に戻る。すぐ揃えたいなら手順 6 をもう一度流す(チェックは入れたままでよい)。
develop を使っている構成では Done が遅れる。 GitHub の Closes #N は既定ブランチへのマージでしか Issue を閉じない。feature → develop の時点では Issue が open のままなので、board は In Progress に戻る。Done が付くのはリリース PR が main に入ったとき。テンプレート既定の GitHub Flow では起きない。

やめるとき

  1. いちばん簡単な止め方 —— 手順 4-1 のシークレットを消す。board への書き込みが止まり、ワークフローは notice を 1 行出すだけになる(CI は赤くならない)
  2. 完全に消す —— .github/workflows/project-sync.yml と、ci.yml の Test project sync ステップを削除する
  3. トークンも片付ける —— 手順 3 の画面に戻り、作ったトークンを Delete する

board そのものは GitHub 側に残るので、不要なら Project の Settings から削除する。

しくみの説明は .claude/docs/project-sync-guide.html。実体は .claude/scripts/project-sync.sh(同期)/ .github/workflows/project-sync.yml(起動)/ .claude/project-sync.json(列名の候補)。
