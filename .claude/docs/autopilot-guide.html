Autopilot 手順書

/next-ticket → /clear の繰り返しを自動化する仕組みの使い方。迷ったらこのページの「早見」と「止まったとき」を見る。

早見

① 始める前に確認
予定だけ表示
bash .claude/scripts/autopilot-loop.sh --dry-run
② 起動(1 回だけ)
裏で動かす
bash .claude/scripts/autopilot-loop.sh --background
③ 様子を見る / 止める
ログ・停止
bash .claude/scripts/autopilot-loop.sh --log
bash .claude/scripts/autopilot-loop.sh --stop
起動したら、あとは GitHub の全体管理 Issue を見るだけ。 autopilot ラベルの Issue「🤖 Autopilot ダッシュボード」に全チケットの状態が出る。一時停止もそこのチェックで行う(スマホの GitHub アプリからでも可)。
人がやること: PR のレビューとマージ(econ では gh pr ready)、止まったときの判断、の 2 つだけ。マージは自動ではしない。

初回の準備

プロジェクトごとに 1 回だけ。リポジトリのルートで行う。

  1. 必要なコマンドが使えるか確認する(gh がログイン済み、jq、claude。econ で使うなら codex も) 
    gh auth status && jq --version && claude --version
  2. チケットが Issue にあることを確認する。 /kickoff(または /setup-tickets)で作った ticket ラベルの Issue が対象。依存は Issue 本文の depends: #12, #15 の形で書く(1 行に複数並べてよい)
  3. 判定が動くか確認する(GitHub は読むだけで、何も書き換えない) 
    bash .claude/scripts/autopilot-next.sh --summary
  4. 無人実行の許可を確認する。 claude -p は途中で確認を求められると止まる。既定は --permission-mode acceptEdits で、Bash は .claude/settings.json の allow にあるものだけが通る。足りなければ allow に足すか、AUTOPILOT_CLAUDE_ARGS で引数を変える
  5. (任意)停止を手元で知る方法を決める。 全体管理 Issue へのコメントは自分の gh アカウントで投稿されるので自分には通知が来ない。気づきたいなら通知コマンドを設定する 
    # 例1: デスクトップ通知(Linux)
export AUTOPILOT_NOTIFY_CMD='notify-send autopilot'
# 例2: スマホに送る(ntfy)。理由が第 1 引数で渡るので、送る処理を小さなスクリプトにする
printf '#!/bin/sh\ncurl -s -d "$1" https://ntfy.sh/自分のトピック名 >/dev/null\n' > ~/autopilot-notify.sh
chmod +x ~/autopilot-notify.sh
export AUTOPILOT_NOTIFY_CMD="$HOME/autopilot-notify.sh"

    環境変数はループを起動するターミナルで設定する(常に使うなら ~/.bashrc などに書く)。

  6. 最初の 1 回は前面で 1 周だけ見る。 全体管理 Issue が作られ、1 チケット目が動き出すのを確認したら Ctrl+C で止め、--background で起動し直す 
    bash .claude/scripts/autopilot-loop.sh

いつもの使い方(通常モード)

  1. 作業ツリーをきれいにしておく(未コミットの変更があると止まる)
  2. 起動する 
    bash .claude/scripts/autopilot-loop.sh --background
  3. あとは放置。ループが「PR の修復 → 新しいチケットに着手 → レビュー待ちなら待機」を繰り返す。1 チケットごとに新しい claude -p を起動するので /clear は不要。待機中は Claude を起動しないので枠を使わない
  4. PR が開いたらレビューしてマージする。マージで空き枠ができると、次の周で次のチケットに進む
  5. 全部終わると全体管理 Issue に「✅ 全チケットが完了」とコメントされてループが終わる
並行の上限: 同時に進める作業は既定で 2 本(レビュー待ちの PR も数える)。PR 1 本がレビュー待ちの間に、依存が解決済みの別チケットを 1 本進める。作業ツリーは 1 つなので、実装そのものは 1 本ずつ順番に行う。

econ モード(Claude の枠を温存したいとき)

.harness/mode に econ と書いた状態で、同じコマンドで起動する(モードの切り替えは人が行う)。1 チケットを 3 段に分け、Claude は計画と PR 作成だけに使う。

1. 計画claude -p "/next-ticket N --plan-only"
design.md を書き切ってコミット
→
2. 実装ループが delegate-codex.sh impl を直接実行
Claude は起動しない
→
3. draft PRclaude -p "/ship-ticket N"
検収なし(CI に任せる)
→
4. 枠が戻ったらgh pr ready 番号
自動レビューが走る → マージ
Claude を使うシェル / Codex(Claude を使わない)人がやる
  • PR は draft で積まれ、マージはされない。同時進行の上限は econ 用に別にあり、既定 4 本
  • package.json の scripts / lint-staged / prepare が変わると止まる → 目視して問題なければ /ship-ticket N を手で実行
  • Codex が使えないと止まる。Claude(Sonnet)に自動では切り替えない
  • draft PR の CI 失敗とコンフリクトだけは Claude で直す(/fix-pr)
  • 委託に向かないチケット(ハーネスのファイルを触る・新しい依存が要る)は autopilot:manual ラベルが付いて飛ばされる → 通常モードで /next-ticket 番号
degraded モード(C)では動かない。 Claude が動かない前提のモードなので、起動してもすぐ止まる。

全体管理 Issue の見方

autopilot ラベルの Issue。最初の判定で自動作成され、判定のたびに書き換わる(内容が変わったときだけ)。各チケットの状態はそれぞれの Issue のラベルと PR が正で、この Issue は一覧表示と操作のためのもの。

表示 意味 人がやること
🔧 要対応 PR にコンフリクト / CI 失敗 / 変更要求がある。ループが次に直す なし(直らなければ止まって知らせる)
👀 レビュー待ち PR が開いている。draft と表示されたら econ の積み置き レビューしてマージ(draft は枠が戻ってから gh pr ready)
🚧 実装中 着手済みで PR がまだ無い なし。長く動かないなら別セッションの放置を疑う
▶️ 着手可能 依存が全部閉じている。空き枠ができたら着手される なし
⏳ 依存待ち 依存先のチケットがまだ閉じていない なし(依存先のマージで解ける)
🙋 手動 autopilot:manual が付いていて自動では進めない 通常モードで /next-ticket 番号
✅ 完了 Issue が閉じている(折りたたみの中) なし

一時停止と再開

本文の 「一時停止」にチェックを入れると、次の周から新規着手も修復もしなくなる。チェックを外すと再開する。ターミナルを触らなくてよい。手で書き換えてよいのはこのチェックだけで、ほかの部分は次の更新で上書きされる。

GitHub に繋がらず一時停止を確認できないときは、安全のため進めずに待つ。

止まったとき

止まると、理由が全体管理 Issue にコメントされ、ログの最後にも出る。まずこれを見る:

bash .claude/scripts/autopilot-loop.sh --log
停止理由(要旨) 対処
作業ツリーに未コミットの変更がある git status で中身を見て、コミットするか破棄してから再起動。再開中のチケット自身のブランチ上の変更なら止まらずに続くので、これは別の作業の変更
前回の実行後も状態が変わっていない Claude が進めなかった(設計判断が要る・同じ失敗の繰り返し)。該当チケットの .steering/ の tasklist.md と design.md を見て、判断を design.md に書き足してから再起動。対話で /next-ticket 番号 を回してもよい
in-progress だが PR もブランチも無い 別のセッションが実装中か確認する。中断なら、その Issue の in-progress ラベルを外す
着手できるチケットが無い(依存が閉じない) 全体管理 Issue の「依存待ち」を見る。依存先が閉じていない / 依存の書き間違い。ベースが develop の場合はマージしても Issue が自動で閉じないので手で閉じる
残りは autopilot:manual だけ 通常モードで /next-ticket 番号 を対話で回す
package.json の scripts 等が変わっている(econ) git diff $(git merge-base HEAD origin/main) -- package.json を目視。問題なければ /ship-ticket 番号 を実行してから再起動
Codex が使えない / 委託が失敗した(econ) Codex の認証・インストールを確認。失敗なら .harness/codex-runs/ のログを見る
Codex のレート上限が 12 回続いた(econ) Codex の枠が戻るのを待って再起動
起動回数の上限に達した 暴走防止の歯止め(既定 20 回)。問題が無ければそのまま再起動
対応するブランチが複数ある 同じ Issue 番号のブランチが 2 本以上ある。不要なほうを消す
判定に失敗した gh auth status を確認。bash .claude/scripts/autopilot-next.sh --summary を直接実行してエラーを見る
既に実行中 二重起動の防止。--stop してから起動し直す
止まらないが通知が来る場合: 変化の無い待機が約 1 時間続くと「進行中の作業が変わっていません」とコメントされる。レビュー待ちの PR が溜まっているか、別セッションが止まっている合図。

対処が済んだら、また起動するだけでよい(続きから再開する):

bash .claude/scripts/autopilot-loop.sh --background

判定のしくみ

毎周 autopilot-next.sh が GitHub の Issue と PR を読み、上から最初に当たったものを行う。

  1. 自分の中断作業の再開 — この作業ツリーにブランチがあり、PR がまだ無いチケット
  2. PR の修復(fix)— コンフリクト / CI 失敗 / 最新のコミットに対する変更要求。マージを早めると後続の依存も解ける
  3. 着手(start)— 空き枠があり、depends: が全部閉じたチケット。優先度 P0 → P1 → P2、同じなら番号の小さい順
  4. 待機(wait)— 進行中の作業がある。pollSeconds(既定 5 分)ごとに見直す
  5. 終了 — 全部閉じた(done)/ 依存が閉じない(blocked)/ 手動のものだけ(manual)

依存先が未マージのチケットには着手しない(ブランチを積み重ねない)。依存を書いていないのに同じファイルを触るチケット同士はコンフリクトしうるが、起きたら修復で base を取り込む。頻繁に起きるなら depends: を足す。

クラウド(Claude Code on the web)で使う

Web のセッションで /autopilot を実行すると、チケットごとに子セッションが起動して並列に進む(コンテナもブランチも別)。子は自分の PR を見張って CI・レビューに対応し、PR の作成とマージを親に知らせる。親は 60 分ごとの見直しを予約して待つ。

  • 通常モード専用(econ では子セッションを起動しない)
  • 変化の無い見直しが 6 回(約 6 時間)続くと親は終了する。再開は /autopilot
  • 全体管理 Issue はローカルと共通

よくある質問

PC をスリープ・シャットダウンしたら?

ループも止まる。復帰後に --background で起動し直せば、GitHub の状態から続きを判定する(状態はループの中に持っていない)。

途中で普通に Claude Code を使って作業してもいい?

同じ作業ツリーで触ると未コミット変更やブランチ切り替えがぶつかる。触る前に全体管理 Issue で一時停止するか --stop する。別のディレクトリ(git worktree)で作業するなら止めなくてよい。

特定のチケットを自動で進めたくない

その Issue に autopilot:manual ラベルを付ける。候補から外れる。

同時進行を一時的に増やしたい / 減らしたい

AUTOPILOT_MAX_IN_FLIGHT=3 bash .claude/scripts/autopilot-loop.sh --background のように環境変数で上書きする。恒久的に変えるなら .claude/autopilot.json。

全体管理 Issue が要らない

.claude/autopilot.json の board を false にする。一時停止は --stop で代用する。

コメントだけのレビュー指摘は拾われる?

ローカルでは拾わない。直してほしい指摘は GitHub で Request changes にする(🔧 要対応になる)か、PR で @claude にメンションする。クラウドの子セッションは PR のイベントで拾う。

実体: .claude/scripts/autopilot-loop.sh(ループ)/ autopilot-next.sh(判定)/ autopilot-board.sh(全体管理 Issue)。詳しい手順は .claude/commands/autopilot.md、econ の規則は .claude/rules/mode/econ.md。
